## Notes

Findings found while preparing this checklist (proposed fixes in the review summary):

- **F1 — Conflict with the owner's technical direction.** The owner requires a **bounded** stream (`limit(20)`) for
  recent messages and cursor-based pagination for older ones. The current plan (research D17) uses an anchored head
  listener **without a limit** (it grows with every new message) and keeps **live listeners** on every older page.
- **F2 — FR-044 depends on that choice.** With a bounded window and one-time older batches, deletions in messages
  outside the window are not live; FR-044 and the handling of messages leaving the window must be redefined.
- **F3 — `startAfterDocument` vs constitution.** `startAfterDocument` needs a `DocumentSnapshot`; passing it through
  the repository/bloc would extend the documented exception. `startAfter([createdAt, id])` gives the same result.
- **F4 — Live arrival while scrolled up / sending while scrolled up** is not specified; FR-041 covers only older loads.
- **F5 — Unread beyond the first 20.** FR-015 says a message is read once viewed, but mark-read clears all unread on
  open even if some were never loaded.
- **F6 — Stale notification wording** remains in the spec (Assumption about the approved notification dependency,
  FR-009, FR-032, US6) despite the 2026-10-31 deferral.

**Resolution (2026-11-01, owner decisions)**: F1/F2 → option A applied (bounded `limit(20)` window, one-time cursor
reads, FR-044 narrowed; research D17). F3 → `startAfter([createdAt, id])` with plain-Dart `MessageCursor`. F4 →
FR-045, FR-046. F5 → FR-015 (opening marks all read). F6 → notification wording marked deferred. UI gaps behind CHK032,
CHK033, CHK037, CHK038, CHK039 → approved as proposed: FR-047 to FR-051. Checkboxes are left for the reviewer.
